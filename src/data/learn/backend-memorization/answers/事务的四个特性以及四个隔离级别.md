# 事务的四个特性以及四个隔离级别

## 面试回答

## 事务的四大特性ACID

Atomicity（原子性）：指的是事务中的所有操作要么全部完成，要么完全不执行。如果事务中的任务部分失败，则整个事务都会被回滚到事务开始前的状态。这样可以保证数据库中不会出现部分更新的情况。



Consistency（一致性）：指在事务开始之前和事务结束之后，数据不会被破坏。例如，A账户给B账户转10块钱，不管成功与否，A和B的总金额是不变的；





Isolation（隔离性）：隔离性确保了并发执行的多个事务彼此之间是隔离的。也就是说，一个事物的执行不应该受到其他事务的影响。



Durability（持久性）：表示事务完成以后，该事务对数据库所作的操作更改，将持久地保存在数据库中



## ACID的实现原理

事务的隔离性是通过数据库锁以及MVCC机制实现的



事务的一致性是通过undo log来保证的，undo log是逻辑日志，记录了事务的insert,delete,update操作，回滚的时候做相反的insert,delete,update操作来恢复数据



事务的原子性和持久性是通过redo log来保证的，redo log被称作重做日志，是物理日志，事务提交的时候，必须先将事务的所有日志写入redo log持久化，事务的提交才算完成



## 事务并发时存在的问题

脏读

脏数据所指的就是未提交的数据，而脏读是指在一个事务处理过程中读取了另一个未提交的事务中的数据。比如，一个事务正在对一条记录做修改，在这个事务完成并提交之前，这条数据是处于待定状态的（可能提交也可能回滚），这时，第二个事务来读取这条没有提交的数据，并做进一步的处理，就会产生未提交的数据的依赖关系。





不可重复读

一个事务先后读取同一条记录，而事务在两次读取之间该数据被其它事务所修改，则两次读取的数据不同，我们称之为不可重复读。例如事务一在读取某一数据，而事务二立马修改了这个数据并且提交事务给数据库，事务一再次读取该数据就得到了不同的结果。



不可重复读和脏读的区别：

脏读时某一事物读取了另一个事务未提交的脏数据，而不可重复读则是在同一事物内读取了前一事务提交的数据，即前一次读到的数据是另一个事务提交前，后一次读到的数据是提交后的。



幻读：

一个事务按相同的查询条件重新读取以前检索过的数据，却发现其他事务插入了满足其查询条件的新数据，这种现象就被称为幻读。幻读是指当事务不是独立执行时发生的一种现象，例如第一个事务对一个表中的数据进行了修改，比如这种修改涉及到表中的“全部数据行”。同时，第二个事务也修改这个表中的数据，这种修改是向表中插入“一行新数据”。那么，以后就会发生操作第一个事务的用户发现表中还存在没有修改的数据行，就好像发生了幻觉一样。



## 四个隔离级别

读未提交

所有事务都可以看到其他未提交事务的执行结果。本隔离级别是最低的隔离级别，虽然拥有超高的并发处理能力及很低的系统开销，但很少用于实际应用。因为采用这种隔离级别只能防止更新丢失问题，不能解决脏读，不可重复读及幻读问题。



读已提交

这是大多数数据库系统的默认隔离级别。它满足了隔离的简单定义：一个事务只能看见已经提交事务所做的改变。这种隔离级别可以防止脏读问题，但会出现不可重复读及幻读问题。



可重复读

这是MySQL的默认事务隔离级别，它确保同一事务的多个实例在并发读取数据时，会看到同样的数据行。这种级别可以防止除幻读外的其他问题。



串行化

这是最高的隔离级别，它通过强制事务排序，使之不可能相互冲突，从而解决幻读、第二类更新丢失问题。在这个级别，可以解决脏读，不可重复读的问题，但可能导致大量的超时现象和锁竞争，通常数据库不会用这个隔离级别。
